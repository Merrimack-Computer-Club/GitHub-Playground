# Contributing to GitHub Playground

These guidelines keep the playground easy to use for everyone practicing here.

## Ground Rules

- This repository contains **documentation only**, so please don't add application code.
- Make your changes on a **feature branch**, not directly on `main`.
- Write clear, descriptive commit messages.
- Open a Pull Request for every change, even small ones.

## Be Kind

Everyone here is learning, from first-time terminal users to experienced students who want more practice. Be patient, keep feedback friendly and constructive, and don't edit or delete other people's practice work. See our [Code of Conduct](CODE_OF_CONDUCT.md) for details.

## Branch Naming

Use this format: `yourname/description`

Examples:
- `peter/add-student-profile`
- `liv/fix-typo-exercise-01`

## Commit Messages

Follow the conventional format:

```
<type>: <short description>

(on the next line) Optional longer explanation.
```

Common types:
- `docs`: adding or changing documentation, like a profile, note, or exercise text. Most changes in this repo are `docs`.
- `fix`: correcting a mistake, like a typo or a broken link.
- `chore`: housekeeping that doesn't change content, like renaming or reorganizing files.
- `feat`: adding something new, like a new exercise or section.

Examples:
- `docs: add Peter's student profile`
- `fix: correct typo in exercise-02`

## Pull Requests

- Give your PR a clear title.
- Mention the exercise you're practicing in the PR description.
- Request a review from a club eBoard member.
- Delete your branch after it's merged.

## Getting Help

Have a question or stuck on something? Open an issue, ask in our [Discord server](https://discord.gg/A4DV423ryu), or contact Peter Hajj at hajjp@merrimack.edu or any other eBoard member of the Merrimack Computer Club.
